# 人物台词与行动日志替换（操作指南）

改台词的唯一数据入口是 `data/action_copy.json`：保存为 UTF-8 合法 JSON，保留键名、只替换右侧文字，重启游戏后加载。
当前工程直接运行支持读取；制作导出包时须把该 JSON 加入非资源文件的导出包含项。
cue 的取用与投影由 `core/action_copy.gd` 与现有日志存档实现（代码即接口）；本文只写 cue 表、命名与写入判据。卡面与候选详情文案的按需契约见 `docs/spec/ondemand-copy.md`。

## 前端文字表达

- 适用于按钮、提示、卡面、详情、日志、对白与旁白等玩家可见文字：禁止过度防御化与过度描写。
- 直接说明当前动作、结果或所需条件；不附加与当前操作无关的免责声明、预防性警告、反复保证或自我解释。
- 同一信息在需要它的位置说清一次；不堆叠同义句、修饰语、重复提醒或与当前场景无关的铺陈。对白与旁白保留人物语气和必要的场景描写。
- 费用、概率、限制、失败原因及不可逆操作的必要提醒属于玩家决策信息，应准确保留；运行时校验不受这项文案指导影响。
- 示例：能量不足时写「需要 2 能量，当前 1」，不再追加「请谨慎操作，以免造成不必要的损失」；行动日志已写结果时，不再重复整段规则说明。
- 此项靠人审：逐句核对其是否提供新信息或必要表达，删去无此作用的内容；不以关键词或固定字数机械裁剪。

## 台词怎么选

- 快感档：`low`（0—39）、`mid`（40—69）、`high`（70—99 或本次行动触发高潮）；取行动前后较高档，避免深呼吸或高潮回落让刚发生的身体反应错档。
- 说话状态：`clear` 清晰；`partial` 普通／马具口球，含混短句；`full` 胶带封口及假阳具口球。完全堵嘴统一 `hero.muffled`，不显示清晰词句或心里话。
- 卡牌台词面：`card.setup`、`card.magic`、`card.strain`、`card.slip`；真实施法优先于其他效果分类，自由／自身准备面归入运作类。施法已经付款但实际失败时改用 `card.magic_failed`，固定火球术改用 `attack.fireball_failed`；该分支只读正式施法结果。
- 不因文案批次获得差分的行动（不要为它们新增 cue）：事件选择、普通道具使用、固定工具使用、挂钩、取回工具、魔瓶存取、结束回合与塔路旅行；姿态等行动实际减费为 0 时仍保留原有操作结果，不伪造能量支付。

## 已留出的台词位

| 键 | 触发条件 |
|---|---|
| `hero.<行动组>.<快感档>.<说话状态>` | 已提交的分组行动，例如 `hero.card.strain.high.partial` |
| `hero.card.magic_failed.*` / `hero.attack.fireball_failed.*` | 已付款且正式判定失败的卡牌／火球施法 |
| `hero.muffled` | 本次操作前或操作后为完全堵嘴，所有行动共用 |
| `hero.climax.<normal/repeated/low>.<clear/partial>` / `hero.climax.full` | 本次正式行动实际触发高潮时的角色发言；完全堵嘴只用共同鼻音 |
| `climax.narration.<normal/repeated/low>` | 高潮时显示在原手牌区的第二人称旁白 |

- 每次成功提交显示一条最新台词，保留到下一次成功操作；没有逐字播放、语音或额外确认。查看、翻面、拖放取消、失败提交不触发新台词。
- 本次行动实际引发高潮时，高潮发言取代该动作原本的高快感台词，继续显示在人物对话框；第二人称高潮旁白单独投影到原手牌区，不进入对白、状态窗口或行动日志。
- 高潮旁白分档：射精前魔力不足 20 用 `low`；同一玩家回合累计第二次及以后或单次连续高潮用 `repeated`；其余用 `normal`。

## 行动日志位

- `enemy.install`／`assembly`／`tighten`／`lock`：施加普通件、施加复合件、加固、上锁。
- `enemy.charge`／`capture_prepare`／`capture`：普通敌人蓄力、收押准备、执行收押。
- `enemy.guard_sequence`／`delayed`／`leave`／`idle`：连动期间附属结果、被打断停顿、离场、无合法目标；`enemy.unseen` 用于未看清的准备动作。
- 事件按 `event.<事件ID>.<动作>` 命名（如 `event.binding_cleric.choose`）；未单独登记的事件动作走 `action.default`。定制时直接添加已存在的事件 ID 与动作组合键，不由正文反推事件逻辑。
- 行动文案可用 `{actor}`（实际行动者名称）与 `{result}`（已经发生的正式结果，默认保留）。可以前后增添描述；人物台词是完整字符串，不提供这些参数。不要删除 JSON 引号，真实换行写作 `\n`。
- 状态变化只记录名称、获得／增加／结束及本次数量（如「施加「皮带增生」，现有 1 层。」）；触发条件、持续时间和完整效果集中在状态窗口。
- 侧栏最新记录在上，滚动查看最近 40 条人物／敌人／事件结果；完整原始结果仍在菜单的行动记录中。未配置的动作用原结果说明；没有台词元数据的旧存档不伪造历史发言。
- 侧栏收起与固定属界面状态：未固定时点击栏外自动收起，固定后点击其他界面仍保持展开；新记录不强制打开已收起的侧栏，重新开始时恢复默认，不修改存档或行动记录。

## 写入判据

- 已删除且不再生成的旧 cue：`hero.attack`、`hero.card.bound/free`、`hero.pose`、`hero.calm`、`hero.end`、`hero.item`、`hero.event`、`hero.default`。旧记录若仍保存这些 cue，投影时直接忽略，不替换成「嗯……」等占位对白；当前没有新分类的零费普通操作也不新增人物对白。
- `core/action_copy.gd` 只解析文本并生成只读显示；正式日志的 `data.action_copy` 保存 cue 与当时的 actor／result，`data.hero_copy` 保存本次说话资格确定后的 cue，`data.climax_copy` 保存同期第二人称高潮旁白 cue，均复用现有日志存档，不新增第二个日志状态数组。
- 修改文字会重新呈现已保存 cue；执行动作、抽牌或重抽随机都不受影响。
- 狱警浮动对白仅在活动牢房流程中展示；离开牢房后历史台词保留在日志，不得在出口战或返塔整备时重新弹出。刑满检查通过的告别台词只在当次返塔起点选择期间例外保留。投影通道：历史日志 `ActionCopy.view → GameView` 按当前牢房／返塔状态过滤 → UI 按阶段展示；不删除日志、不写游戏状态。
- 新增行为／台词条件必须在对应提交处确定稳定 cue：不能用中文正文推断规则，不能在 UI 修改游戏状态。怪物从原敌人执行入口登记，连动子动作沿普通操作入口；事件完成后只登记一条结果摘要。
- 需要更细的卡牌、情绪或表情分支时，在 `core/action_copy.gd` 的接口上增加结构化条件，不用测试台词替代实际机械结果。
