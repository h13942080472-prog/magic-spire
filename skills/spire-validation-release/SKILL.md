# 验证与发布（spire-godot）

## 审查流程

审查触发与豁免见根 `AGENTS.md`「实现规约」。按本次变更影响选择模型，不按文件数量升级：

| 审查范围 | 模型 | 推理强度 |
| --- | --- | --- |
| 文档核对、引用追溯、日常代码、局部接口与测试维护 | `gpt-5.6-terra` | `medium` |
| 核心契约、架构边界、事件／状态迁移、事务／回滚、存档、发布或审查门禁规范 | `gpt-6-astra` | `low` |
| 关键问题存在复杂交互，补充证据后仍不能可靠判断 | `gpt-6-astra` | `medium`，仅升级该问题 |

- 模型和强度在启动时显式指定；初审不继承完整聊天历史，只提供目标、必要约束、变更文件与契约入口、验证范围及证据路径。
  审查者独立核对差异和证据，不把实现者的结论当作通过依据；先读摘要，需要追溯失败或矛盾时再打开详细日志。
- 一批变更默认一位审查者，文档、代码、测试合并审查；仅在存在可独立验收的不同风险域且并行有实际收益时拆分，
  不让多个代理重复扫描同一范围。审查代理不再派生代理。
- 按改动影响追溯调用方与必要依赖；未受影响且契约证据有效的模块不展开内部。
  复用源码、测试输入及相关环境未变的证据，不为“独立”重复运行同一检查；缺少证据、发现矛盾或新风险时才补查。
- 发现报告只列可定位的问题、影响、证据或复现方式，以及实际审查范围和未验证部分。
  返修交回原审查者复核受影响差异；原审查者不可用时，交接发现与证据，不默认重新全面扫描。
- 已发现问题解决、受影响验证通过且约定范围无阻塞问题时结束；不例行加开第二轮全面审查。
  未验证范围如实报告；属于完成条件的缺失证据仍须补齐，不能靠标记“未验证”跳过。

## 验证与证据

- 命令、范围展开与退出码语义统一见 `skills/repo-ops/SKILL.md`。先按影响选分类，共享规则用 `-Impact` 合并一次跑；
  测试器自身改变才加 `-VerifyRunner`，素材首次导入或新增时才加 `-Import`；完整回归与发布要求按任务及 `docs/spec/packaging.md` 执行。
- 核对退出码、完成标记与 `summary.json` 的源码指纹；`source_changed` 不得当作冻结版本通过，按操作技能重跑原选范围。
  修复失败后也检查是否影响上轮通过分类；`-RerunFailed` 不能代替这些分类的复验。
- 测试复用现有分类与真实输入助手，按变更覆盖正例、最近反例、边界及必要回滚；不新增镜像测试，不删有效失败断言。
  等价覆盖须对应同一行为与失败模式；不能只因用例名称或测试步骤相似就删除。
- 敏感性实验只针对新增／修改的检查或有证据缺口的判据；无关旧检查不逐次重做，专题契约明确要求的实验仍须执行。
- 测试存档用隔离目录，不读写玩家存档；正常数值试玩与缩短生命的夹具明确区分。不默认生成截图，必要截图只作补充证据。
- 同一交付批次的运行结果与审查结论合并登记到 `docs/record/verification.md`，注明范围、源码依据、失败和未验证部分；
  日志留在忽略目录，不将全文复制入记录。纯错字、链接、格式修正可只在交付说明列检查结果。
- 推送与发布授权见根 `AGENTS.md`「禁区」，打包先读 `docs/spec/packaging.md`；代码规范见根 `AGENTS.md`。
